# GitHub Actions – Hosted & Self-Hosted Runners
Project Link - https://github.com/SuryaKunabi/GitHub-Actions.git

## What is GitHub Actions?

GitHub Actions is a CI/CD automation platform provided by GitHub. It allows you to automatically **build, test, and deploy** your application when events occur in a GitHub repository.

---

##  Basic GitHub Actions Workflow

A workflow is defined using a YAML file inside:

```text
.github/workflows/
```

Example:

```yaml
name: CI Pipeline

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Run Test
        run: |
          echo "Running tests..."
          echo "Build completed successfully"
```

# GitHub-Hosted Runners

GitHub-hosted runners are virtual machines managed by GitHub.

You don't need to create or maintain the server.

### Example

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
```

Other commonly used labels include:

```yaml
runs-on: ubuntu-latest
runs-on: windows-latest
runs-on: macos-latest
```

### How it works

```text
GitHub Repository
       |
       | Workflow Trigger
       ↓
GitHub Actions
       |
       ↓
GitHub-Hosted Runner
       |
       ├── Checkout Code
       ├── Install Dependencies
       ├── Run Tests
       └── Build / Deploy
```

### Advantages

* No server setup
* GitHub manages the runner
* Easy to start
* Suitable for most CI/CD pipelines
* Pre-installed development tools

# Self-Hosted Runners

A self-hosted runner is a machine that **you manage and connect to GitHub Actions**.

It can be:

* AWS EC2
* Physical server
* Virtual machine
* On-premises server

Example:

```yaml
jobs:
  build:
    runs-on: self-hosted
```

You can also use labels:

```yaml
jobs:
  build:
    runs-on: [self-hosted, linux, x64]
```

# Example: AWS EC2 Self-Hosted Runner

You can configure an Ubuntu EC2 instance as a GitHub Actions runner.

### Architecture

```text
GitHub Repository
       |
       | Workflow Trigger
       ↓
GitHub Actions
       |
       ↓
AWS EC2
(Self-Hosted Runner)
       |
       ├── Checkout Code
       ├── Install Dependencies
       ├── Run Tests
       └── Deploy Application
```

### Basic Setup

On the Ubuntu EC2 instance:

```bash
sudo apt update
sudo apt install -y curl
```

Go to:

```text
GitHub Repository
      ↓
Settings
      ↓
Actions
      ↓
Runners
      ↓
New self-hosted runner
```

Select:

```text
Linux
x64
```

GitHub provides commands to download and configure the runner.

The general process is:

```bash
mkdir actions-runner
cd actions-runner

# Download the runner package
# Extract the package

./config.sh --url https://github.com/USERNAME/REPOSITORY --token YOUR_TOKEN

./run.sh
```

> Use the exact download and configuration commands generated by GitHub because the runner version and commands can change.

# Example Using GitHub-Hosted Runner

```yaml
name: GitHub Hosted Runner

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Test
        run: |
          echo "Running on GitHub-hosted runner"
```

# Using Runner Labels

Labels help select a specific self-hosted runner.

For example, a runner can have:

```text
self-hosted
linux
x64
aws
```

Workflow:

```yaml
jobs:
  build:
    runs-on: [self-hosted, linux, x64]

    steps:
      - uses: actions/checkout@v4

      - run: echo "Running on Linux self-hosted runner"
```

# When to Use Which?

### GitHub-Hosted Runner

Use it when:

* You want quick CI/CD setup
* You don't want to maintain servers
* Your workflow doesn't require special infrastructure
* Standard Linux, Windows, or macOS environments are sufficient

### Self-Hosted Runner

Use it when:

* You need custom software or tools
* You need access to private infrastructure
* You need a specific environment
* You want greater control over the runner machine
* Your workflow needs access to internal systems
